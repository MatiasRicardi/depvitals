## Selected correction family

**F1: explicit Node preload flags in supported script prefixes.** This is one bounded family with
value in two real roots. Node documents the `--require` and `--import` preload mechanisms in its
[minimum-runtime CLI reference](https://nodejs.org/download/release/v22.13.0/docs/api/cli.html).
The static recognizer covers exact `node`, existing leading assignments, `-r MODULE`,
`--require MODULE`, `--require=MODULE`, `--import MODULE`, `--import=MODULE` and the no-argument
`--test` flag before a script operand or `--`. It does not run Node or resolve the selected modules.
An unknown/malformed prefix option or eval/print/loader/compact flag discards all preload candidates
in that Node segment, including valid preloads before the rejected option. Existing outer command
credit is preserved; an opaque shell segment retains its ordinary no-credit rule.

Module selectors use the existing package-specifier classifier and declared dependency/devDependency
gate. No executable mapping is applied to a module selector (`tsc` is not automatically `typescript`).
Preloads suppress unused only; they never create missing findings or peer/optional-only evidence.

[Authored controls](../../test/fixtures/external-corpus/repros/node-preload-flags.json) specify 31
positive/negative before/after cases. The selected F1 change removes only `tsx` from ts-extras unused dev
and `@babel/register` from preact-render-to-string unused dev. Other arrays are unchanged; both roots
still exit 1. F1 recognizes these script hints in the v0.4.0 target.

Reports retain the script JSON pointer, the exact module selector and its ordinal among candidate
events across the entire script. Earlier declared or undeclared events shift later ordinals.
The evidence variant `via: "node-preload"` sorts after `runner`.

**F2 and F3: no additional family selected.** The integrated freeze accepted both no-selection
decisions for their respective owner steps.

## Investigated and deferred candidates

- `cross-env`: absent from the pinned corpus. An authored wrapper example reproduces that only the
  outer wrapper is credited. Recursive wrapper support is outside F1 and is deferred.
- `require.resolve()`: absent from the corpus. A legal literal example is currently not recognized;
  a new source construct/provenance variant is not selected without demonstrated corpus demand.
- Ambient Node types: present in two roots; existing regression/contract deliberately avoids blanket
  inference from globals/builtin imports. Keep the limitation visible; no general types/tsconfig
  resolver is selected.
- Local bindings named `require`: no actual code binding occurs in these snapshots. Authored controls
  confirm parameter ownership is already supported, while a local ESM variable still produces a
  false source reference outside the supported general-binding scope. A larger binding resolver is
  deferred and is not described as a shipped correction.
- Babel/Verb/Changesets/hook configuration: explicit references exist, but new detector surfaces are
  outside this bounded selection. `xo` activation and `rollup` use remain unresolved.

The five authored investigation examples and 31 F1 controls were compared against the baseline CLI;
source syntax was accepted without evaluation. No red future regression suite was committed.

never fetch the corpus. The optional evaluator argument `--reviewed-baseline` binds a **REVIEWED**
