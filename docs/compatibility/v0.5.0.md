## Measurement boundary

Host is Linux `7.3.4-1-cachyos`, `x64`, Intel(R) Core(TM) i7-10510U CPU @ 1.80GHz,
8 logical CPUs (8 available), 33287602176 bytes RAM.
Tools are Node `v26.6.0`, pnpm `11.28.3`, Python 3.14.10; no tool or dependency upgrades.
These are local observations on a shared host, with warm filesystem caches and no CPU pinning.
They are not timing thresholds, cross-platform guarantees or final-release performance claims.

Each row uses two warmups followed by five fresh Node processes. Common modes alternate baseline
and target first on successive pairs. Diagnostic-only rows use the target. Python's monotonic
`perf_counter_ns` brackets `Popen` through `wait4`, including Node startup, scanning, rendering,
file capture and process completion. It excludes Python startup, fixture generation, installation,
identity hashing and result verification. Each sample must match its fresh verified reference's
status and exact stdout/stderr bytes. Output files have a 32 MiB per-file limit, the child timeout is
20 seconds, and an outer 25-second helper timeout bounds orchestration.

GNU time is unavailable here. [Python `os.wait4`](https://docs.python.org/3.14/library/os.html#os.wait4)
returns resource usage for the exact reaped Node child. On Linux,
[`ru_maxrss`](https://man7.org/linux/man-pages/man2/getrusage.2.html) is the kernel's maximum resident
set size in KiB. The helper records that high-water value, rather than an RSS-at-exit estimate.
The instrument control measured 51884 KiB for a minimal child and
118188 KiB when a child allocated and touched an additional 64 MiB.
The control is separate from the cost samples. Tables show median (observed minimum–maximum),
RSS converted to MiB, and captured stdout bytes. Source bytes count supported source file bytes only.
JSON sizes include the literal absolute project path; another acquisition path can change those sizes.
Raw channels, metrics and all five samples are retained locally in the harness output directory.

## Reproduce from tracked files

Use Linux with Python 3 supporting `os.wait4`, supported Node and the locked development dependencies.
Acquire all six entries from both catalogs using the
[data-only acquisition recipe](../../test/fixtures/external-corpus/README.md#reacquire-an-exact-snapshot).
Verify each exact commit/tree and archive hash before extraction. Do not install or execute targets.
Create a JSON root map outside the repository, keyed by the six IDs above with absolute export paths,
for example `{"is-number":"/path/to/is-number", ...}` with all six entries and no ellipsis.
The comparator verifies both parsed-catalog digests, review status and full selected-root snapshots.
No ignored planning files are needed.

From this source checkout, with the exact `packageManager` pnpm on PATH, prepare separate packages
and consumers. Acquisition may use the network; both consumer installations and measurements below
are offline. Baseline npm acquisition must resolve the exact hash above, which the harness enforces.
Keep this shell open to retain the scratch path, and set `roots_file` to your complete root map.

```sh
roots_file=/absolute/path/to/roots.json
comparison_dir="$(mktemp -d /tmp/depvitals-comparison.XXXXXX)"
mkdir -p "$comparison_dir/baseline" "$comparison_dir/target" \
  "$comparison_dir/baseline-consumer" "$comparison_dir/target-consumer"
pnpm run clean
pnpm run build
npm pack depvitals@0.4.1 --ignore-scripts --json \
  --pack-destination "$comparison_dir/baseline" > "$comparison_dir/baseline/pack.json"
npm pack --offline --ignore-scripts --json --cache "$comparison_dir/cache" \
  --pack-destination "$comparison_dir/target" > "$comparison_dir/target/pack.json"
node --input-type=module - "$comparison_dir" <<'JS'
import { readFileSync } from 'node:fs';
import { join } from 'node:path';
import { execFileSync } from 'node:child_process';
const scratch = process.argv[2];
for (const role of ['baseline', 'target']) {
  const [pack] = JSON.parse(readFileSync(join(scratch, role, 'pack.json'), 'utf8'));
  execFileSync('npm', ['install', '--offline', '--ignore-scripts', '--no-audit', '--no-fund',
    '--cache', join(scratch, 'cache'), '--prefix', join(scratch, role + '-consumer'),
    join(scratch, role, pack.filename)], { stdio: 'inherit' });
}
JS
node scripts/compare-corpus.mjs \
  --baseline-root "$comparison_dir/baseline-consumer/node_modules/depvitals" \
  --baseline-archive "$comparison_dir/baseline/depvitals-0.4.1.tgz" \
  --target-root "$comparison_dir/target-consumer/node_modules/depvitals" \
  --target-pack "$comparison_dir/target/pack.json" \
  --roots "$roots_file" --output "$comparison_dir/results"
```

The comparator identifies the current metadata version from the target pack result, so the same
recipe also works after the planned version bump. Retain `results/receipt.json` and `results/captures/`
locally. The receipt records all metric samples, source/artifact identities, host and calibration.
It refuses an existing output directory and fails on input/artifact drift, incompatible reports,
unexpected process channels, truncation or missing metrics. Historical evaluator modes are unchanged.
Routine tests use authored report fixtures, not network acquisition or these upstream exports.
