# DepVitals v0.4.0 candidate notes

**Unreleased.** The target package version is 0.4.0. Local consumer validation currently uses a
development tarball at package version 0.3.0.

## What changes

- Use `--format json` for a version 1 scan document and `--explain <package>` for an exact package
  explanation in terminal or JSON. Reports include supported usage evidence, declaration groups
  and effective exclusions. The package includes the [schema and examples](../../schemas/README.md).
- JSON scans and explanations skip the optional update notifier, including in interactive terminals.
  The default terminal scan retains its concise report and existing notifier eligibility.
- Use the [fixed-version CI recipe](../examples/ci/README.md) to install from a committed lockfile,
  preserve report, diagnostics and status, and distinguish findings from operational errors and
  invalid artifacts. The current development tarball was tested in an isolated consumer.

## Compatibility and migration

Normal v0.3 scan commands remain valid. `depvitals why` still selects a directory named `why`.
A full scan returns 1 for findings or operational errors. Use stdout and stderr to distinguish
them. Explanation exit status is scoped to the requested package after a full scan. Keep CI on
the full scan and update machine consumers to the versioned schema.

The selected F1 correction recognizes supported explicit Node preloads in package scripts. In
the four pinned external projects, only two findings changed from v0.3.0. The `tsx` finding in
`ts-extras` and the `@babel/register` finding in `preact-render-to-string` were removed from unused
devDependencies. Both have retained preload evidence. The other projects and findings matched
the reviewed baseline. The [corpus ledger](../compatibility/v0.4.0.md) records identities, remaining
findings, six explanation checks and local cost measurements.

If you are moving from Depcheck, follow the [manual migration guide](../reference.md#manual-migration-from-depcheck)
to translate flags and deliberate exclusions and update JSON consumers.

## Scope and remaining limits

DepVitals scans one selected root inventory using static JS/TS, JSX/TSX and declaration-file
references plus bounded script and ESLint/Jest hints. Script and config hints can prevent unused
findings for declared packages. Only supported source references can create missing findings.
Exclusions narrow the report. Review the project and test changes before removing a dependency.

General binding resolution, `require.resolve()` evidence, recursive `cross-env` wrappers,
workspace aggregation, ambient-type inference, inherited tsconfig resolution, arbitrary tool
configuration and automatic fixes are outside this release scope. The corpus leaves `xo` and
`rollup` unresolved and retains the three intentional nested-demo findings. See the
[technical reference](../reference.md) for supported patterns and error handling.
